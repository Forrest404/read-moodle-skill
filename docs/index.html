read moodle skill

by Forrest · November 2026

I got tired of clicking through four Moodle modules every week to find out what was due and what I was meant to read, so I wrote a few commands for Claude Code that do it for me. Now I type /deadlines or ask "what's the brief for the case study?" and it reads Moodle and tells me.

It only reads. It can't submit, post or change anything on Moodle. That's enforced in the code, not just written in the instructions.

Installing it

You need a Mac with Claude Code. Paste this into Claude Code and it will set everything up:

Install https://github.com/Forrest404/read-moodle-skill for me. Read SETUP.md and follow it step by step.

During setup your browser opens Moodle. Log in like you normally would, and when it asks to open "MoodleKey", click Open. That's how it gets read access to your account. Then Claude asks which of your courses are actual modules and checks your term dates with you. It took me about five minutes. Restart Claude Code at the end and the commands are there.

What you can do with it

  • /today: what's due soon, this week's sessions and readings, and any new announcements
  • /deadlines: everything due in the next two weeks, and whether you've submitted it
  • /brief case study: reads the assignment brief and marking criteria and explains what you actually have to hand in
  • /module MEDI0001 week 7: one module's week, with slides and readings
  • /grades: your marks and a summary of the feedback
  • /plan: breaks your deadlines into smaller steps and puts them in your calendar (it shows you the plan first)
  • /assignments and /ask for anything else

You don't have to use the commands. Asking "what do I need to read before Thursday's seminar?" works too.

This is roughly what /deadlines gets back from Moodle before Claude tidies it up (module names changed, links cut):

Deadlines in the next 14 days:
- Mon 23 Nov 23:56 (in 2 days) | MEDI0001 | Short film | not submitted
- Fri 04 Dec 13:00 (in 13 days) | MEDI0003 | Proposal | submitted

What it touches

It uses Moodle's web-service API, the same one the official Moodle app uses, with a key tied to your account. It never sees your password. On your Mac it adds:

  • a folder at ~/read-moodle-skill with the code, your settings and any briefs it downloads
  • the commands, in ~/.claude/skills
  • a tiny app called MoodleKey that catches the key when you log in (built on your Mac during install)
  • the key itself, in your Keychain

If you connect Notion during setup, /today can write to one Notion page and /plan can add rows to one database. Apart from that, the only things that leave your Mac are the requests to Moodle and whatever you ask Claude anyway.

Things to know

  • I've only tested it on UCL Moodle. Other universities' Moodle sites might work if they allow the Moodle app.
  • Mac only for now.
  • If UCL ever switches off access for the Moodle app, this stops working too.
  • Some coursework is handed in on Turnitin or other systems, so "not submitted" on Moodle doesn't always mean you missed it.
  • Opening moodle.ucl.ac.uk/webservice/rest/server.php in a browser shows "invalid token". That's normal. It's an address for programs, not a page.

If it breaks

Run python3 -I ~/read-moodle-skill/moodle.py doctor. It checks each piece and tells you what to fix. If your key stops working (after a password change, say), run it again with login instead of doctor.

To update: cd ~/read-moodle-skill && git pull && ./install.sh
To remove it: ~/read-moodle-skill/uninstall.sh, then delete the folder.

Bugs and ideas go on GitHub issues. All the code is on GitHub too, if you'd rather read it before running it. You should.
